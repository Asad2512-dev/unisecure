# Notifications

UniSecure uses Laravel database notifications as the notification record of creation and read state. `NotificationService` creates the recipient-scoped record and queues `DeliverNotificationJob` for each active device token. `notification_deliveries` distinguishes queued, attempted, accepted and failed provider delivery; provider acceptance is not proof of device receipt or user reading.

`GET /api/v1/notifications`, `GET /api/v1/notifications/{notification}`, read and read-all routes are authenticated and ownership checked. Device tokens are registered and revoked only for the authenticated user and are never serialized.

Class reminders are generated by `notifications:class-reminders`, scheduled every minute. They use actual session times, the `class_reminder_lead_minutes` setting, skip cancelled sessions and use an existing notification for idempotency.

Administrators with the existing `users.view` permission can inspect `/admin/notifications` and delivery attempts. Only failed `provider_unavailable` or `transient` deliveries below `FCM_MAX_ATTEMPTS` can be retried. Retry requests are POST/CSRF protected and audited; queued retry, provider acceptance and recipient read state remain separate.
